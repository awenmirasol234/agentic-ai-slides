Agentic AI in Software Development

Agentic AI: The Evolution of AI in Software Development

From AI-assisted coding to autonomous software engineering.

Slide 02 // Core Definition

What Is Agentic AI?

An AI system capable of pursuing a goal by planning tasks, making decisions, using tools, executing actions, and evaluating results with varying degrees of human supervision.

01

Goal-Oriented

Works persistently toward a high-level defined objective rather than answering a single prompt.

02

Autonomous

Performs chained development tasks and intermediate steps without needing constant human prompts.

03

Action-Oriented

Directly interacts with external systems: editors, terminals, compilers, databases, and test runners.

04

Adaptive

Reads compiler errors or test failures and dynamically adjusts its approach based on real outcomes.

Software Development Example

Instead of asking AI to generate a single login function, you instruct it to implement an entire authentication feature—including database schema integration, input validation, and automated tests.

Slide 03 // Paradigm Shift

Traditional AI vs. Agentic AI

Traditional AI
Reactive Assistant
  • Responds directly to individual prompts
  • Generates isolated code snippets
  • Suggests theoretical solutions
  • Waits passively for next human instruction
  • Developer manually coordinates every step
Example: Fixing a Login Bug Explains the error message you pasted and suggests a snippet of code for you to copy and test.
Agentic AI
Goal-Driven Executor
  • Works toward overarching engineering goals
  • Implements complete end-to-end features
  • Executes solutions directly using workspace tools
  • Determines appropriate next steps autonomously
  • Manages multiple connected actions in sequence
Example: Fixing a Login Bug Investigates the codebase, identifies the root cause, modifies the files, runs the test suite, and verifies the fix.
Key Takeaway

Traditional AI primarily assists with individual requests, while Agentic AI executes multiple connected actions toward an objective.

Slide 04 // System Capabilities

What Makes an AI Agentic?

01

Autonomy

Can perform assigned tasks without constant human intervention.

02

Planning

Breaks complex engineering objectives into smaller, actionable tasks.

03

Reasoning

Analyzes code context and trade-offs to determine appropriate actions.

04

Tool Usage

Interacts with terminals, APIs, databases, and development environments.

05

Memory & Context

Maintains relevant project architecture information and previous decisions.

06

Adaptability

Evaluates test or runtime outcomes and adjusts strategy when something fails.

Important Distinction

Simply using an LLM or chaining multiple AI models does not automatically make a system agentic. Its ability to pursue goals through decisions and actions is what matters.

Slide 05 // The Agentic Execution Cycle

How Does Agentic AI Work?

STEP 01

Goal

Understand the developer’s high-level objective and constraints.

STEP 02

Planning

Break down the objective into smaller, sequenced tasks.

STEP 03

Execution

Perform concrete actions using available workspace tools.

STEP 04

Observation

Inspect terminal outputs, compiler logs, errors, and test results.

STEP 05

Evaluation

Determine whether the current outcome satisfies requirements.

STEP 06

Iteration

Correct problems and repeat until achieved or human input is needed.

Practical Example: Student Management System
  • 1. Analyze the system requirements
  • 2. Design the database schema
  • 3. Develop the frontend & backend
  • 4. Run the application locally
  • 5. Test student registration & authentication
  • 6. Fix identified runtime or test errors
  • 7. Verify the completed implementation

Slide 09 // Summary & Outlook

Benefits, Challenges, and Conclusion

Key Benefits
Velocity & Focus
  • Faster end-to-end development workflows
  • Reduced repetitive programming tasks
  • Parallel execution of development work
  • Automated testing & verification assistance
  • More time for architecture & problem-solving
Core Challenges
Risk & Governance
  • Risk of incorrect code and flawed decisions
  • Potential security vulnerabilities
  • Increased computational and API token costs
  • Agent coordination and integration complexity
  • Continued necessity for skilled human supervision
Conclusion & Closing Statement

“Developers may no longer need to write every line of code themselves, but they will still need to understand, direct, and validate the systems they build.”
